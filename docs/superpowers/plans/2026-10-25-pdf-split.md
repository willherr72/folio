# Editable PDF Splitting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline, task by task. No implementation delegation; one final scoped review.

**Goal:** Export the current edited workspace as a previewed batch of editable PDF parts.

**Architecture:** Frontend computes contiguous ranges; native validates the complete snapshot, prunes bookmarks and composes each part through Save. Handle-bound publication and atomic cancellation reuse existing batch primitives.

**Tech Stack:** React/TypeScript, Tauri/Rust, PDFium/lopdf, Vitest, existing Windows acceptance harness.

**Spec:** docs/superpowers/specs/2026-10-25-pdf-split-design.md

## Global constraints

- 1..10,000 pages, 1..1,000 contiguous nonempty parts covering all pages once; zero-based half-open indexes on wire.
- 512 MiB existing per-PDF cap, 1 GiB batch cap; sequential buffers.
- Assembly permissions required for every source; Save protection policy; no flattening.
- New Folio split-UUID folder, part-0001.pdf names; no overwrites or recursive cleanup.
- No commits, releases, original changes, or parity claims. Preserve failed artifacts.

## Review focus

- Later denied part must create no folder (task 1).
- Top-level out-of-order and repeated bookmark destinations must retain leading pages and partition once (task 2).
- Links to excluded pages, bookmark ancestors and editable form values must remain valid (task 1/3).
- Cancel before registration, during work, after commit, and after unmount must respect ownership (task 1/2).
- Existing image export folder ownership must remain unchanged (task 1/3).
