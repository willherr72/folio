# Graph-preserving form composition implementation plan

> Execute inline with superpowers:executing-plans in the existing isolated worktree. User-authorized autonomous work; preserve inherited changes and packages. One builder check and one final review, no implementer delegation or commits.

**Goal:** Preserve editable forms and document structure when combining, selecting and duplicating PDF pages.
**Architecture:** Canonical read-only ownership inventory, staged defaults/resource merge, typed projection/occurrence changes, then language/action/public Save integration.
**Tech stack:** Existing Rust/lopdf/PDFium, Tauri/TypeScript and independent Python PDF readers.
**Spec:** `docs/superpowers/specs/2026-10-30-structured-form-composition-design.md`.

## Constraints and review focus

Inventory: cumulative 4,000 nodes, 100,000 steps, depth64, 16 MiB metadata. Retained graph: existing 100,000 objects, 1,000,000 values, 256 MiB stored bytes. No payload clone before reservation, no renderer or limit changes. Aliases must not create distinct logical owners; existing tags/opaque references must not follow retired widgets. Same names and differing fonts across sources must not merge answers or change later fill. Hidden/nonvisual fields and calculation targets survive appropriate selection. Unsupported actions/languages remain explicit guards.
