> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline in the existing isolated worktree. Standing user authority opts out of routine approval; one final reviewer, no per-task delegation or commits.

**Goal:** Produce and verify an optimized desktop/CLI/MCP portable package of the accepted post0.26 functionality.
**Architecture:** Validate and retain baseline evidence, prove a version-only runtime delta, build through existing guarded packaging, then verify extracted binaries with actual editing/recovery/automation and independent saved-file checks.
**Tech Stack:** Rust/Tauri, React/TypeScript, PowerShell, Python, Playwright, pypdf/MuPDF.
**Spec:** `docs/superpowers/specs/2026-10-31-portable-027-design.md`.

## Global constraints

Version0.27.0-dev.1; preserve0.26 and all originals/failures. One heavy build/Cargo process, locked/offline, existing shared target. No source changes during validation/build. No fake full-suite pass: retain original native failure and corrected-target evidence. No new dependencies, external publish, commit, user-app restart or private PDFs in the package. WebView2 remains required. Broad resource, metadata, printing/accessibility and parity limits remain open.

## Review focus

1. Version normalization must not authorize changed dependency/runtime/renderer bytes: isolated negative controls in Task1.
2. A ZIP can be complete but unsafe or different from the executable being tested: archive verifier controls plus extracted binary identities in Tasks2–3.
3. Checkout resources can mask a broken portable build: outside-checkout paths, invalid cwd renderer and embedded OCR checks in Task3.
4. Correct appearance alone can hide lost forms/tags/links or changes to another page copy: original-source independent audits and corruption controls in Task3.
5. Numeric PID reuse can contaminate memory or cleanup decisions: creation-time-bound sampler and verified owned-process stop in Task3; no unrelated process termination.
