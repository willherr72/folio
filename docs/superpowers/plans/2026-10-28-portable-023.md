# Portable 0.23 Implementation Plan

> Use superpowers:executing-plans inline. One final scoped reviewer; no routine
> confirmation, per-task agents, commits, publication or cleanup.

**Goal:** a verified optimized Windows desktop/CLI development package containing
the reviewed editing and automation improvements since0.22.0-dev.1.
**Architecture:** reuse the existing versioned staging, immutable fingerprints,
combined archive verifier and owned-process acceptance harnesses.
**Tech Stack:** PowerShell, Python, Rust/Tauri, npm/Vitest, existing WebView workflow.
**Spec:** docs/superpowers/specs/2026-10-28-portable-023-design.md

## Global constraints

Version0.23.0-dev.1; preserve0.22.0-dev.1 and all originals/artifacts. No feature or
dependency changes unless a demonstrated package regression requires correction.
One Cargo, locked/offline, jobs1, serial tests, established shared target. Never
change product/test inputs during a live gate/build. No new test merely mirroring
a version bump: existing integrity tests plus real package acceptance own the proof.

## Review focus

1. Version/renderer mismatch or stale executable: validate metadata and all hashes
   at build, extraction and final acceptance (tasks1–3).
2. Existing destinations or source files overwritten: preserve prior files and
   run repeated-build refusal plus original hashes (task3).
3. Workstation-relative resources hiding incomplete packages: run outside checkout,
   default renderer resolution and offline OCR smoke (task3).
4. Debug-only evidence mistaken for release behavior: all runtime acceptance uses
   the extracted optimized executables and records their hashes (task3).
5. Documentation overclaims compatibility or points to obsolete executables:
   reconcile README/changelog with completed checkpoints and explicit limits;
   check included guide paths and reviewed baseline provenance (tasks1,3).
