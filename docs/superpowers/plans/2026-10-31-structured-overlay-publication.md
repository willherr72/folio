# Graph-preserving overlay publication implementation plan

> Execute inline using superpowers:executing-plans in the existing isolated worktree. Standing user authority opts out of routine approval. One builder check (complete) and one final milestone review; no implementer delegation or commits.

**Goal:** Save added and imported editable overlays on combined/selected/repeated structured PDFs while preserving original document relationships and later editing.
**Architecture:** Isolated generated-only appearance rendering, trusted imported-annotation lineage, bounded occurrence-specific graph attachment, typed tag/language maintenance, then public integration and cross-route acceptance.
**Tech stack:** Existing Rust/lopdf/PDFium/Tauri/TypeScript; independent pypdf/MuPDF audits.
**Spec:** `docs/superpowers/specs/2026-10-31-structured-overlay-publication-design.md`.

Each is tested in the owning task below. External signatures/actions remain guarded as before.

**Interface:** `WorkerRuntime::prepare_structured_overlays(&ExportRequest, &mut impl FnMut()->EngineResult<()>) -> EngineResult<PreparedOverlays>`. `PreparedOverlays` owns a generated-only lopdf Document and per-request-page bindings (`overlay_id`, generated `annotation_id`) in overlay order. It also retains the exact source geometry/unit used by rendering. Neither source page payloads nor source catalogs are imported. Render all pages as editable annotations in staging; later publication chooses annotation attachment or flattening. The function validates request identity/geometry/assets and budgets before rendering; source permissions are still enforced by the outer public transaction.
