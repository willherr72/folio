# Aggregate resource limits for text-removal input

Previous goal turn made progress: native multi-page preview transactions,634library passes and independent saved-output acceptance. Exact checkpoint hashes revalidated. This milestone resolves allocation amplification during initial lopdf loading, before existing redaction kernel admission. User delegated routine decisions and opted out of permission questions.

## Decision
Add an opt-in vendored `Document::load_mem_with_resource_limits(buffer, ResourceLimits)` API. It uses the existing parser with strict loading and no filter/password/recovery; ordinary load APIs retain current behavior. Redaction selection uses this API. Avoid a second PDF parser or rejecting all object streams: compressed object streams and incremental cross-reference sections remain supported within explicit budgets.

ResourceLimits bounds input bytes, aggregate decoded bytes (including each filter layer and unfiltered object/xref stream copies), parser object-node attempts, aggregate copied object payload bytes, and cross-reference/index entries. Folio defaults:64MiB input,64MiB decoded,128MiB copied object payload,1,000,000 node attempts and200,000 xref/index entries. Existing kernel100kobject,64MiB decoded-content/output and other semantic limits remain. These are logical allocation/work bounds, not an exact process-memory guarantee or general PDF security certification.

Use a thread-local scoped budget around the synchronous in-memory load. No public ambient-budget setter. Nested budget activation refuses rather than resetting a parent allowance; Drop restores prior context on success/error/unwind. All bounded loading stays sequential, including object-stream member parsing, even when Rayon is enabled. Ordinary unbounded loads retain parallel behavior. Each charge is monotonic; parse retries and discarded objects consume budget. Exhaustion is sticky and checked before returning any document, so parser alternatives, optional objects, or xref recovery cannot hide it. Reject encrypted input before encrypted raw-object collection in this opt-in route; source policy already excludes it from redaction.

## Allocation coverage
- Input length checked before any parse.
- Charge object attempts before recursive direct/container parsing; charge dictionary keys, names, literal/hex strings before allocation. A zero-allocation lexical span check may conservatively charge encoded source length, including nested string-copy costs. Existing nesting caps remain.
- Charge raw stream copies before `to_vec` and delayed stream filling. Cross-reference repeats and repeated Length references consume the same budget.
- Limit each decompression stage by the remaining aggregate decoded allowance, then charge its actual output. Enforce on unfiltered clones as well. Bounded decoder scratch and predictor intermediate buffers remain documented overhead; no output-size-only check after an unbounded decode.
- Bound classic xref entry collection and xref-stream rows before map allocation. Object-stream index collection is charged before Vec growth. Object members use the same parser-node/payload context; repeated/overlapping offsets cannot multiply allocations past the budget.
- Disable parallel iterator paths only for a scoped bounded load. No new thread-wide effect after the guard drops.

Additional traced requirements: validate predictor dimensions with checked multiplication and charge PNG previous/current/output buffers before allocation; count or transfer compressed-object and trailer clones; charge header/binary-mark payloads. Add a separate scoped indirect-reference resolution-depth guard (64) that persists even when compressed Length lookup creates a fresh cycle HashSet. Bound decoder intermediate output before optional recovery; a limit error marks the scoped context exhausted even when a caller ignores the immediate error. Tests must cover huge predictor rows and compressed-Length recursion without risking a process-sized allocation or stack overflow.

Add vendored lopdf Rust/TOML sources to the normal build fingerprint so this dependency change cannot escape artifact provenance.

## Verification
TDD adversarial tests with small configurable budgets: many individually admissible compressed object streams exceed the aggregate cap; many small direct objects/arrays and large strings exhaust nodes/payload; classic and streamed xref/index counts exhaust entry budgets; duplicate object-stream offsets cannot amplify payload; source input limit; successful loads at boundary and below; failed load followed by ordinary load and a fresh bounded load; concurrent independent budgets; nested/unwind guard restoration where accessible. Exercise compressed ObjStm and incremental xref success. Verify no budget error is swallowed into a partial successful document.

Run relevant existing loader/recovery regressions, redaction focused tests, library gate and prior240mapping/48saved-output replay. Native preview candidate bytes must remain identical for the accepted three-page fixture. Ordinary malformed/recovered reader behavior remains unchanged in compatibility tests. One design builder check, one final review, consequential fixes locally with RED/GREEN tests. No public UI, new package or original-file writes; public host/composition integration remains next.

## Builder-check dispositions and decoder policy
All six design questions are resolved in implementation scope: actual decoder production is charged at the capped reader/writer or byte append before growth, including discarded/error paths; PNG output and row scratch are charged separately. Classic rows and every ObjStm index token consume entry units before collection, including free/duplicate records. Top-level/parser dictionary roots, header/binary-mark data and nested literal copies consume the shared counters. Compressed member and Prev ownership is moved rather than cloned. Indirect resolution is separately capped at64. Structural auxiliary maps/vectors are bounded multiples of already charged nodes/entries.

The bounded route intentionally refuses reader reconstruction/offset recovery, Flate/LZW decoder errors that the ordinary reader may recover, and the nonstandard Brotli large-window escape (low seven header bits0x11) before decoder construction. Standard Brotli windows remain supported up to2^24; native decoder scratch/allocator overhead is additional to the logical payload ledger. Ordinary loader APIs retain their recovery/decoder behavior. This is an explicit compatibility boundary for structural rewriting, not a universal strict-decoding claim. Built-in format scratch (zlib/LZW state and standard Brotli tables/window) is not an exact process-wide budget. A failed budget remains sticky even through parser alternatives and delayed Length handling.
