## Approach

Use the existing combined portable builder and extracted-runtime qualification,
with exact five-file `0.41.0-dev.1` to `0.42.0-dev.1` version substitution.
The user authorized autonomous continuation and opted out of routine questions;
this is the implementer's integration choice, not a new user requirement.

Promoting the bare component executable would omit distribution/extraction and
regression qualification. Repeating every native test solely for version strings
adds little evidence if byte equality is proved. Instead, qualify the actual
fresh corrected 2,729-pass/32-ignore native result only when implementation,
renderer, dependency/shared inputs and membership are identical apart from those
five exact metadata files. Reject newline/whitespace/feature edits. If that
condition fails, diagnose and obtain a fresh native gate before packaging.
Frontend tests, normal combined release builds and extracted acceptance are fresh.

## Limits

This packages the existing corrected implementation. It does not broaden List
admission, add desktop candidate Preview, change dependencies, relax source
preservation or finish commercial parity. Broad producer/font/script/transform,
printing/signature/accessibility, worst-case latency/RSS and other-host work remain
open. Some lone-row painted Lists refuse without observed band authority.
