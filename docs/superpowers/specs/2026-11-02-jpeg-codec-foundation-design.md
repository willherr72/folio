# Bounded JPEG coefficient codec foundation

This implements section 2 of the JPEG area-redaction plan. It is a private native component, not JPEG admission in the PDF publisher or a public redaction feature. Preserve the full parent design, including coefficient removal plus independently verified opaque fill and the later publication/UI gates.

Vendor the unmodified official libjpeg-turbo 3.2.1 source verified by upstream asset digest c27ad72a68da151177929aa969ae773a2da5ac2af9ce946079314fdac8cece7f. Build its static codec through a small CMake wrapper with SIMD/arithmetic/TurboJPEG disabled. Replace only the system allocation backend through the wrapper's source list, without editing upstream files. Rust's build script invokes CMake in OUT_DIR, aligns the MSVC CRT with the Rust target, and links the static result. No application subprocess is used. Include all codec/native/build inputs in source fingerprints and its IJG/BSD license/provenance in the existing license collector.

The Rust boundary validates complete JPEG marker/entropy framing and exact EOI consumption before native work. Admit 8-bit baseline/progressive Gray/RGB, bounded dimensions and common supported sampling, immutable 8-bit nonzero quantization tables, direct caller-provided PDF transform interpretation with Adobe precedence, and no profiles or unsupported coding modes. Marker/scan counts and coefficient work are bounded. Expected dimensions/components must match the PDF caller's declaration. An MCU mask contains exactly one 0/1 byte per unit; the rewrite never changes the caller's bytes.

Default ceilings: input/output 64 MiB, dimensions 32,768, 16 million pixels, native allocation requests 192 MiB, 64 scans, 4,096 markers, and 512 million conservatively counted coefficient visits. Callers may lower resource limits. Check remaining work before codec execution, and allocation/output limits before allocation/growth. These count owned allocation payloads plus bookkeeping, not exact process RSS.

The whole-operation work reservation is padded component blocks times 64 times `(input scans + 3)`. The extra passes conservatively cover initialization, mask replacement and baseline encoding. Rust and C enforce the same reservation before coefficient decoding. Exact output limits permit a fully occupied final buffer; a context-owned sentinel distinguishes an exact fit from the first excess byte without allocating another output buffer.

Color admission follows PDF ColorTransform/Adobe precedence. Markerless RGB component IDs can disagree with a PDF request for YCbCr, including the three-component default. Refuse that ambiguous case unless the caller explicitly selects no transformation; do not substitute one reader's heuristic. Also refuse JFIF/Adobe color markers after the first SOS, because the decoder has already fixed its interpretation. Ordinary EXIF/COM between scans remains admissible and is stripped. This narrows ambiguous-input admission while retaining the original preservation requirement. See [PDF 32000-1:2008, table 13](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf) and the pinned PDFium `libjpeg_scanline_decoder.cpp`/upstream `jdapimin.c` implementation.

All native state lives in a heap context stable across setjmp. Each libjpeg allocation is tracked in a context-owned linked list with size/alignment accounting. Compressor and decompressor share the same budget; destination growth uses the same allocator. No backing-store files are permitted. Error exits and warning-based recovery are contained inside C. Destroy codec state and free any remaining tracked allocations on every exit, including partially initialized states. The returned output has a dedicated C release function; Rust uses RAII and a fallible bounded copy. The app must not terminate on malformed input.

Copy critical coefficient encoding parameters but do not copy source metadata markers. Preserve source JFIF/Adobe marker presence and effective transform behavior; do not introduce an Adobe marker that would override a PDF ColorTransform setting. Generate only minimal necessary color markers and drop unrelated metadata/density/thumbnail content. Zero selected AC coefficients and use the parent design's bounded black DC constants with the effective PDF color interpretation. Do not confuse this with full-area opacity; the later publisher supplies verified fill.

Tests must first demonstrate the missing capability, then cover eight owned sources, unchanged source bytes, zero/nonzero MCU masks, marker and entropy failures, metadata stripping, quantization/color cases, exact output/work/memory refusals, repeated failure cleanup and independent outside-coefficient/raster evidence. Inspect native peak/retained allocation accounting without assuming a memory hint is enforcement. Review the entire foundation before connecting the real publisher. Generalized geometry, selected-area fill, page graph ownership and public Windows acceptance remain in the parent plan.
