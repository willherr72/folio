# Native editing subphase diagnosis

Continue the standing Folio quality goal by identifying the dominant native costs on the generated 300-page dense PDF and its proved two-page derivative. The previous turn qualified and promoted portable036; that checkpoint, launcher, original PDFs and prior evidence stay unchanged. User standing autonomy authorizes inline execution without design questions. This is diagnostic progress, not a promised speedup.

## Approach

Use a default-disabled Cargo feature, `native-profiling`, and an example driver exercising the real public PdfEngine worker API. Scoped timing calls compile to unit values without this feature. A matched control uses the same optimized instrumented executable with recording disabled. Comparing historical GUI timing or opt-level=0 unit tests would confound the boundary being investigated. External CPU profilers add tooling and do not directly identify the already-established transaction phases, so start with small explicit spans.

A process-wide collector is enabled only by the example driver. Sessions are exclusive, bracket one synchronous public engine operation, and admit spans from exactly one worker thread. Nested records contain only fixed static labels, integer IDs/parents and monotonic start/end nanoseconds; never PDFs, strings, arguments, source IDs, paths or result buffers. Limit records to4096 and depth128. Overflow, wrong-thread spans, unclosed/out-of-order spans and concurrent recording invalidate the diagnostic without changing operation results. Stale guards cannot write into another session. No allocation, lock or clock call exists at instrumentation sites when the feature is disabled.

Measure open-source stages (retained capture, renderer load, all-page annotation admission, bookmarks, physical units), discovery (isolation, serialized baseline, font proof/snapshot, source mapping, context/admission), and replacement (source/font context, isolated edit, graph publication, reopen, exact verification, annotation-source retention). Instrument nested durations; exclusive time is inclusive minus direct children only. Never sum nested or overlapping intervals into wall time or call them CPU time.
