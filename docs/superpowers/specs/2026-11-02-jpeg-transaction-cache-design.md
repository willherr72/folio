# Transaction-owned image reuse

Continue parent JPEG phase 3. The previous ownership stage verified record/coefficients/paint and fresh publication, but every prepare still creates a fresh registry. A multi-page edit repeats those expensive validations. Introduce an explicit ImageContext for one edit; never a global cache or a cache keyed only by ObjectId across documents.

Choose an owned context containing a registry over shared Rc/RefCell state. Each prepare borrows the context mutably and begins a document scope, clearing only its ObjectId alias table. Returned immutable image Arcs may outlive that borrow. A bounded content cache survives the successive source/intermediate/probe prepares. Standalone registries retain their existing semantics; only an explicit context enables cross-pass reuse.

Validate the complete admitted dictionary interpretation before looking up input content. Cache keys bind encoded bytes, dimensions/components, effective JPEG transform and coverage claim, or raw/Flate filter and validated predictor interpretation. Unknown or malformed fields must not gain authority from a hit. A hit may reuse coefficient/record proof; it never validates a page occurrence's paint, clipping or path context. Seed the corresponding fresh serialized-image key after successful ownership, so reopening Folio's canonical output does not redo codec work. Registry ObjectIds are document-local only.

Bound cache cardinality, source input, decoded source retention, variant retention, codec work, hash work, and geometry work explicitly. Charge attempted native work even on failure; failed content never enters the cache. Preserve64MiB source input/retention and64MiB variant retention as separate pools, plus512 million aggregate coefficient work and512MiB hash input. Cache at most512 distinct owned payloads and1024 input aliases; at most256 uncached source attempts. The final publisher still enforces its own64MiB total output-image and PDF bounds. These are logical payload/work limits, not a promise of exact RSS.

Variant requests bind source identity and exact normalized selection. Admit only immutable sources owned by this context; preserve coverage union, account before expensive work/allocation, and seed fresh output keys for later reparse. Repeated aliases/requests return the same Arc and do not consume another codec pass or retained-payload charge. Keys include color and coverage semantics even when coefficient bytes happen to match.

Thread the same context through area preparation, glyph inspection, range removal/replay, space probes and the source-bound area transaction. Keep defaults for unrelated text-only callers. Avoid resetting the aggregate budget between document scopes. General JPEG page admission remains gated until source canonicalization, ImageWork, conservative disclosure and final integrated review are complete.

Acceptance: same ObjectId in different documents cannot return stale data; repeated source and canonical output use the same immutable allocation; changed color, predictor or coverage cannot reuse an incompatible result; failure/retry remains bounded and unpoisoned; exact work/input/hash/cache/retained endpoints; repeated owned variants/save/reload; existing raw/Flate and saved corpus equality; serial ordinary native regression. This context is a step toward whole-edit integration, not public JPEG redaction approval.
