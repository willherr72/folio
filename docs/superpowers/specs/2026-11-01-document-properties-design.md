# Document properties and deliberate removal

Continue toward everyday PDF-editor parity with inspectable, editable document properties. Use the existing Rust/Tauri/React architecture. Standing autonomous authorization replaces routine design questions; these are implementer choices, not newly claimed user decisions.

## Approach
Changing only the first page's source would make edits disappear when that page is moved or deleted. Mutating every source would change unrelated source ownership and history. Instead keep an optional document-level metadata edit in EditorDocument history/recovery and apply it to the final PDF before encryption and atomic publication. Unchanged documents retain current Save behavior. This is the chosen approach.

Inspect Title, Author, Subject, Keywords, Creator, Producer, creation/modification dates, Info/XMP presence and conflicts from the current leading source. Editable fields are Title, Author, Subject and Keywords; untouched fields/custom values remain unchanged. The editor resolves Info values first and otherwise uses XMP default values, reporting differing values. Update both Info and the corresponding XMP property for fields explicitly changed. Title/Subject update x-default while retaining other language alternatives; an empty edit stores an empty default value. Author edits replace the author sequence with one supplied author string; disclose this when multiple authors exist. Keywords remain one literal string. XML aliases/entities and UTF8/16/32 use the existing bounded parser, not regular-expression XML rewriting.

Use source-range edits to retain custom RDF/XML and qualifiers. Support conventional RDF Description properties, simple attributes, title/description Alt arrays, creator Seq arrays and qualified rdf:value forms. Ambiguous/unsupported target structures fail before publication rather than flatten unrelated metadata. Missing properties/packets are created with locally declared namespaces; packet declaration encodings remain valid. Requests use a tagged Update/Remove variant, four optional fields,16KiB UTF8 per field, XML1.0 characters only; reject empty updates/unknown keys. Apply bounded copying, cancellation checkpoints and existing4MiB XML limits. Preserve original source files, page streams, annotations, forms, links, tags and protection policy.

“Remove document properties” explicitly removes document Info and catalog XMP, including custom properties, without requiring malformed packets to parse. Its UI states that page/object metadata, attachments, comments and visible text are outside this operation. It is not a whole-document sanitization claim. Remove unreachable obsolete objects so detached document metadata is not written to the copy; retained page/object aliases remain intact. Changes remain Undo/Redo-able until Save; reopening the output reflects the new metadata. Redaction discards pending property edits so removed metadata is not resurrected.

Carry the same draft through editable/flattened Save, extraction, split PDFs and protected-copy export. Permission checks require content editing on sources contributing to the document; inspection remains available. Source/adapter/tab ownership and stale async reads must follow existing dialog patterns. Recovery validates the tagged edit and limits before adoption. Dirty tracking includes property edits without changing existing unedited digests.

## Acceptance
Watch focused failures before implementation. Test namespaces, escaped Unicode, multilingual Alt/defaults, author sequences, empty values, preserved custom/qualified RDF, conflict inspection, alias privacy, cancellation/bounds, malformed removal, obsolete byte absence, original-byte preservation and no-op behavior. Native exports cover complete-source and composed/structured routes, protection and split output. Frontend tests cover dirty/Undo/Redo, source reorder, recovery, modal draft cancellation, async stale ownership and every export path. Fresh desktop edit/Undo/Redo/Save/reopen/removal/recovery plus independent readers/pixels and one final scoped review precede acceptance. Existing packages remain untouched; no parity claim.

Primary references: [Adobe Dublin Core](https://developer.adobe.com/xmp/docs/xmp-namespaces/dc/), [Adobe PDF namespace](https://developer.adobe.com/xmp/docs/xmp-namespaces/pdf/), [Adobe XMP basic](https://developer.adobe.com/xmp/docs/xmp-namespaces/xmp/).

Implementation clarification: Update supports clearExisting:true when adding values after removal; retain that flag through later edits to prevent resurrection. Reset to source explicitly clears the override. XMP edits target the empty-about RDF subject when present, otherwise the first subject, retaining other subjects.
