# Large-document edit attribution

The accepted larger-document session proves fidelity but not responsiveness or a retained-history memory budget. Its mixed readiness metric combines UI preparation, native execution, rendering and automation. Diagnose these boundaries before changing ownership or history.

Use the exact optimized large-document candidate and its generated 300-page dense fixture. Create a one-page derivative whose first-page MuPDF text, glyphs, geometry and RGB pixels match the source; preserve original bytes. Execute seven alternating header edits in fresh, isolated profiles: a 300-page control, the same workflow with bounded IPC timing, and the one-page workflow with IPC timing. Seven is sufficient to distinguish repeated fixed cost from first-use work without another 100-action stress run. Save final output and close each tab; verify original/even and odd states, Undo/Redo and saved output.

Approaches considered: static estimation cannot establish which boundary dominates; a rebuilt instrumented native worker adds build/profile variables before the slow boundary is known. Start with an observational wrapper around the existing Tauri invoke function, returning the exact original promise and preserving receiver, arguments, results and errors. Store only scalar metadata, command/source identities and start/end times, never response buffers or argument objects. Limit the log to 4096 rows and fail diagnostic acceptance on overflow or instrumentation errors. A paired control records the same UI phases without the wrapper. These measurements include observer overhead and native queue time; they are not CPU profiles or acceptance budgets.

Record discovery/dialog preparation, replacement input, Apply-to-dialog-dismissal, and text/raster-ready durations separately. Attribute native calls by command and phase; do not sum overlapping call durations into wall time. Observe successful source creation/close acknowledgements, not unobservable private engine documents. Sample identity-bound process memory at empty, open, each edit, and post-close idle; no Network, Tracing, emulation or forced GC. The existing 6 GiB operational stop is retained as a stop, not a quality budget.

Source analysis will connect the observed dominant boundary to the worker path. Only a demonstrated cause justifies a product correction; any correction needs a reproducing regression and fresh affected verification. No automatic history reduction, cache eviction, or disk cleanup is authorized by this diagnostic design. Preserve accepted packages, failures, sources and unrelated edits. Standing user authorization covers inline execution without design questions. This is a short diagnostic design, not a new product architecture.

Observed platform amendment: the packaged Tauri 2.11.5 invoke property is read-only; the first observed run refused installation before opening a document. Preserve that failed attempt and its masked-finally error. The replacement observer wraps writable browser fetch, which the exact dependency's IPC script calls. It returns the original promise and never reads/clones response bodies or request headers. Parse at most 65,536 request characters solely to copy sourceId; retain no other payload. End timing at response headers, so durations include queue/native/transport time but exclude response-body parsing and callback delivery. Record successful close acknowledgements and source identities in edit requests; do not claim direct observation of created source IDs or private engine objects. Existing no-Network/Tracing/GC constraints remain. Control workflow logic is unchanged; observer import/installation and failure-safe log flushing are the only session differences.

Control refinement: also copy an optional nonnegative integer pageIndex from the same bounded request parse. Preserve the earlier observer's missing page metadata as a limitation. Require final-app readiness before installation after a startup attempt lost its observer before opening. Add a two-page derivative, proving both source pages' raw glyph dictionaries, geometry and RGB pixels unchanged, to match the 300-page view's two mounted canvases. This controls mounted-page count; encoded size, total pages and other document contents still change together. No one-factor claim about page count alone is warranted.
