# Composition resource controls

This implements the loading/serialization gate of the structured-composition design, not a new merge architecture. The previous graph relocation primitive is verified; the full combined Save workflow remains the acceptance objective.

Reuse the vendored lopdf opt-in bounded loader. Add a controlled variant that returns both the document and remaining logical resource allowances. Its cancellation probe is an owned `Arc<dyn Fn() -> bool + Send + Sync>` so existing `Arc<PdfSaveControl>` can be captured without exposing its atomic state, unsafe borrowed pointers, a polling thread, or a second cancellation authority. The existing bounded-loader API delegates with no probe; ordinary loaders retain existing behavior. Probes run outside thread-local RefCell borrows. Cancellation is sticky within a scope, and scope disposal restores thread state after errors or unwinding.

Check cancellation at scope entry/exit, accounting checkpoints, decoder checkpoints already provided by bounded decoding, and periodic long-token scanning checkpoints. This is cooperative cancellation, not a hard real-time latency guarantee: individual codec/parser operations may take time between checkpoints. Keep all existing parser count/byte/decompression refusals. Input byte allowance decreases once per successful load; remaining work allowances reflect all parser attempts, not just retained objects.

Connect this loader to `CompositionGraph::import_bytes`. Parse one immutable input at a time, then use the already-tested relocation transaction. Store remaining parser allowances only on successful import; if a load/import fails, abort the composition request without publishing or mutating its prior graph. Budget totals accumulate across successful sources. This controls logical parse work and retained graph size independently; it is not an exact RSS claim. Keep the parsed-document primitive private to the module once bounded entry is available.

For serialization, wrap the existing BoundedWriter with cancellation checks before writes and between at most 64 KiB chunks of large writes. Retain the exact cancellation error and never return partial bytes, even if an underlying writer error is handled. Check again after serialization. Connect this function to the complete-source and imported-graph final serialization points that already have a Save monitor. Uncontrolled callers retain the same bytes and existing 512 MiB output limit. Atomic publication and its commit boundary remain unchanged.

Tests cover classic/object-stream input, remaining budgets across sources, refusal/cancellation recovery, probe unwinding and thread isolation, unchanged successful text/objects, large-write cancellation, sticky serialization failure, unchanged input/destination, and successful controlled Save. The complete structured-composition refusal stays in place. No desktop/package acceptance is claimed for this stage.

Coordinator decision: extend existing accounting and writer boundaries rather than creating a separate parser/serializer or a thread that periodically checks cancellation. Standing user autonomy supplies authorization; no routine approval question is needed.
