# Exact accented encoding equivalence

User goal: continue Folio toward useful and faithful existing-PDF editing. The user has authorized autonomous implementation and opted out of design questions. This is a component of the broad goal, not a substitute completion target.

A valid named WinAnsi or MacRoman encoding dictionary that redundantly assigns its exact literal accented glyph names must retain the same eligibility as the named base. Existing proof of actual source bytes, glyphs, Unicode, font widths, permissions, geometry and appearance remains mandatory. Do not rewrite source encodings, reconstruct meaning from Unicode aliases, silently substitute fonts, or add dependencies. Unsupported base encodings, undefined entries, remaps, duplicate assignments, indirect cycles, malformed/oversized arrays and glyph-name aliases remain refused. Exact nominal duplicate glyph names, including WinAnsi byte 127/bullet, must retain the named-base source policy. Standard and explicit-Unicode examples refuse an actual source alias; a verified implicit-WinAnsi embedded font retains its existing accepted no-op/glyph proof. Metadata equivalence adds no new source authority.

Approaches: guessing equivalence from Unicode would conflate distinct glyph identities; duplicating tables risks divergence. Chosen implementation shares the existing pinned literal encoding tables between the CFF verifier and equivalence recognizer, and compares exact byte names. The original ASCII policy remains covered. Named tables and font proof behavior otherwise stay unchanged.

Acceptance: observed RED for accented dictionaries; direct/indirect WinAnsi/MacRoman positives; wrong-base names, Unicode aliases, malformed ranges, duplicate assignments and undefined bytes refused; standard and embedded TrueType edit/save/reopen/re-edit preserve encoding and neighboring text; paragraph and nested-form routes covered; original bytes unchanged. Independent saved-file glyph/font/encoding/paint and fixed-mask pixel checks plus actual corruption controls. A normal compiled CLI proves successful original-font editing. Native and frontend gates retain their stated profiles. Fresh scoped final review, then one correction pass if required. No new package, version, launcher, private input or clipboard changes.

Reference: Adobe describes named encodings as codepoint-to-glyph-name maps in the official [PDFont reference](https://opensource.adobe.com/dc-acrobat-sdk-docs/acrobatsdk/apireference/PD_Layer/PDFont.html), with the literal definitions in PDFReference AppendixD. This change uses exact glyph names, not inferred Unicode equivalence.
