# Structural redaction

## Intent and authority
Folio needs real removal of selected PDF information as a missing everyday workflow. The user authorized autonomous implementation toward Adobe/Foxit usefulness and opted out of routine design questions. Design choices below are coordinator decisions, not previously user-selected requirements. The previous goal turn made progress by closing the fixed-fixture paragraph geometry gap. The broader goal remains active.

## End-state workflow
Mark text or rectangular areas on selected page occurrences, inspect a preview that identifies all affected content, apply in one undoable in-memory transaction, then save a new redacted copy. Apply removes selected text glyphs, image pixels and intersecting graphics from the output data. Cover marks merely show the removed area. Document-wide metadata/attachment sanitization is explicit and reported. Search/copy and low-level decoded-resource inspection must agree that removed material is absent. Unmarked content stays searchable/editable with preserved appearance; whole-document rasterization is not the normal route. Original files and pre-Apply drafts remain unchanged. Undo/recovery may intentionally retain the original in the user's private workspace; exported redacted copies must not contain it. Never imply that deleting the original local file securely erases storage.

## Approaches
1. Opaque overlays leave underlying data and are not redaction.
2. Whole-page raster reconstruction removes vectors/searchability and is unsuitable as the general editing workflow. Pixel replacement is appropriate for actual source images, not a substitute for normal PDF text removal.
3. Structural rewrite plus fresh, bounded graph publication is selected. Reuse Folio's source-ownership, occurrence, permission, preview and atomic-save machinery; never trust generic page-save/prune alone as proof of erasure.

## Architecture and staged delivery
A. Private structural text-removal kernel: consume an already loaded lopdf Document; parse/canonicalize an admitted page program, bind inspected text-block selections to the complete canonical page content, erase all text-show operands in selected BT/ET blocks, and build a completely new minimal PDF graph. This first milestone is an internal primitive, not an exposed redaction tool or certification of area redaction. It proves actual input-to-output removal and metadata non-retention on a bounded operator/font subset.
B. Native geometry and broader content: bind selections/regions to the immutable engine source and physical geometry; split partial glyph ranges while preserving following advances; mask intersecting source-image pixels with alias isolation; remove affected path objects with visible preview of any removal outside a mark. Handle nested forms, clipping, tags, font-resource minimization and old replay hints. Source resources must not retain removed payloads (including unused custom glyphs/ActualText). Unsupported cases refuse with the draft intact.
C. Full-document publication: preserve unaffected page occurrences and supported connections; sanitize metadata, attachments/actions and alternate text without reattaching source graphs. Forms/annotations require explicit preserved appearance and removal semantics. Protected documents use existing rights and security policy. Output is a fresh non-incremental file with no hidden originals or stale previews. Verify decoded streams, object reachability, independent text and raster preservation.
D. Desktop/CLI/MCP: share one inspected/preview/apply engine transaction, clear mark-versus-applied state, save-copy semantics, authorization, cancellation and source-generation checks. Reopening a redacted copy cannot undo redaction; undo of the open working document remains intentional. Do not expose the tool until its supported content/security contract and complete acceptance are met.

## Milestone A contract
New private module `src-tauri/src/redaction_core.rs` and tests. No worker command, public crate API, UI or release claim in A. Its input is an already loaded Document, so new file parsing/decryption is not introduced; engine input parse budgets remain an integration requirement for B/C.

Admitted pages have canonical zero-origin MediaBox, dimensions 1..20000 pt, Rotate 0 and UserUnit 1, with matching optional crop/trim/bleed/art boxes. Resolve inherited boxes/resources through a validated, acyclic page tree of at most 1000 unique pages and depth 64. Reject annotations, forms, optional content, transparency groups, output intents, signatures and unknown rendering-dependent catalog/page keys. Known non-rendering metadata is omitted; report omitted categories. Do not copy any original object graph. Root/Info/trailer IDs, attachments, unused resources, comments, arbitrary alias names and Folio hints cannot survive solely because they existed in the source.

Use only the twelve standard Latin Type1 faces with default or explicit WinAnsi encoding; reject used font overrides/descriptors/ToUnicode/differences/embedded programs. Rebuild used resources under generated F0... aliases. Unused source resource graphs are omitted without traversal. All text strings are printable ASCII (0x20..0x7e); inspect all pages before returning success. Future font support must not mistake font names for source-authority proof.

Canonical operators comprise validated balanced q/Q, BT/ET; finite standard affine/text positioning and numeric text state; gray/RGB/CMYK colors; standard path construction/painting/clipping with no string operands; and Tj/TJ/single/double quote text shows. Unknown operators, inline images, Do/gs/shadings, marked content, text clipping/invisible render modes and malformed operands refuse. Preserve all non-show state operations. Erasing a double-quote show preserves its word/character-spacing assignments; quote movement can be retained as T*. Entire BT block selection avoids altering the position of unselected glyphs inside that block; partial glyph selection belongs to B. No claim that this kernel removes overlapping vector/image content in a selected visual rectangle.

Inspection yields page index, BT-block index, decoded source text and an opaque SHA-256 selection ID covering the canonical full-document page programs/geometries/fonts plus block identity. Recompute on removal; stale/duplicate/unknown/empty selections refuse. The kernel returns fresh bytes and removed-block count, with no selected text echoed into metadata. Selection bounds/black paint are added only by the later verified geometry planner.

Limits: at most 100,000 parsed document objects inspected, 1000 pages, 100,000 total decoded operations, 8 MiB decoded per page, 64 MiB total decoded content/output, 4096 targets, 1 MiB total visible text, nesting/reference depth 64. Check decompression with the existing bounded lopdf API, cumulative counters before growing buffers, finite numeric bounds and exact operand shapes. Unknown/malformed states fail atomically without an output handle. These are additional-allocation bounds for the kernel; hostile initial PDF parsing is not newly solved or claimed.

## Acceptance
For A, actual synthetic input PDFs contain selected secrets in Tj/TJ/quote shows and redundant copies in comments/Info/XMP/unused resources/unreachable streams. Fresh output must retain unrelated text/positions, preserve quote text-state effects and contain none of those removed copies, even after decoding every emitted stream. Shared source content/font aliases and page-tree inheritance cannot cause cross-page edits. Unselected visible repeats intentionally remain unless separately selected. Test stale/duplicate targets, partial arrays, cycles/depth, malformed operators/numbers, unsupported rendering semantics and size budgets. Independent MuPDF/pypdf compare text and pixels outside selected text ink; no black overlay is involved. One scoped review before accepting the kernel. Later stages require separate partial-glyph/image/form/tag/security/desktop/automation acceptance and do not inherit a redaction claim from A.

## Design review rulings
Before generic strict content decoding, run a bounded lexical admission pass that recognizes names, literal/hex strings and comments, rejects inline-image BI syntax before decoder entry, and counts at most 500,000 lexical tokens across the document with nesting depth 64. Limit each operation to at most 16 top-level operands and array elements to 4096; reject dictionaries/references in content. Count operations before materializing the generic operations vector. This pass only admits bounded syntax; Content::decode_strict and typed operator validation remain authoritative, so no permissive partial parse is accepted. Text inspection reports decoded ASCII operands rather than claiming independent reader Unicode semantics; default StandardEncoding remains distinct from WinAnsi when rebuilding fonts.

Before dropping unused resource categories, resolve the effective ColorSpace dictionary through bounded references and reject DefaultGray/DefaultRGB/DefaultCMYK bindings. They are implicit rendering dependencies, even without cs/CS. Named color spaces without an admitted referring operator remain unused and are omitted. The design review is artifacts/redaction-core-20261029/design-review.md; its two questions are settled here. No second design reviewer is required.

## Implementation review corrections
The preflight numeric grammar consumes a complete PDF number (one optional leading sign, at most one decimal point, at least one digit). Adjacent signed/decimal prefixes refuse before the allocating parser, with decoded operand/array checks as defense in depth. The final review reproduced the original numeric ambiguity and permissive Flate prefix recovery.

Milestone A admits uncompressed content or directly named FlateDecode with absent/null DecodeParms. It uses a new opt-in bounded strict method in vendored lopdf; complete zlib termination, checksum and exact compressed-input consumption are required. The ordinary reader recovery method is unchanged. Other filters, predictors and trailing compressed bytes refuse. This additional file scope avoids a new dependency and does not broaden the public API of Folio.
