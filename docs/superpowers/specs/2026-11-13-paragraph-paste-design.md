# Multiline paste from existing text into paragraph editing

Make multiline pastes usable while editing an existing PDF text object. Today the single-line dialog rejects CR/LF clipboard text, and Edit paragraph transfers only the old input. Use the established styled paragraph draft preparation and source/font ownership, with no PDF write until Preview/Apply.

## Approach

The executor chooses an explicit staged **Paste as paragraph** action after a multiline paste. The input and original draft stay unchanged until preparation succeeds. Alternatives: silently flatten line breaks (loses intent), automatically enter the paragraph editor on paste (surprising mode change), or redesign existing-text editing around a second multiline editor (duplicates the existing workspace). The user's standing opt-out covers routine design/approval questions; these are executor choices.

Normalize Windows CRLF and lone CR to LF, splice at the captured input selection, retain surrounding typed content, and put the paragraph caret after the inserted text. Reject unsupported controls, unpaired surrogates, split grapheme boundaries, empty results and replacements beyond the existing 4096 UTF-8-byte paragraph capacity. Never silently truncate. Ordinary single-line input remains limited to1000UTF-16units. Paragraph transfer now admits normalized LF hard breaks and4096UTF8bytes; native mapping/layout/publication limits remain unchanged.

Keep a pending immutable replacement/range in the dialog. Only expose the action when a paragraph callback exists. Typing or another paste invalidates stale pending content; font changes may retain it and the action uses the current font, copied/leased through the existing transfer route. Busy state disables actions; failed preparation keeps both typed input and the pending paste available, and while staged, single-line Apply is disabled and the paragraph action becomes Paste as paragraph. Discard paste restores the prior selection/draft and ordinary Edit paragraph action. Text-only/older adapters retain the existing single-line rejection. Do not include pasted content in error messages or logs.

Use React/TypeScript and the existing paragraph transaction. No dependencies, native/Rust, renderer, permission, clipboard-write, version or packaging changes.
