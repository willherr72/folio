# Preserve ordinary document metadata during Save

Folio must not discard titles, authors, multilingual descriptions, rights or custom XMP properties merely because a Save uses page composition. Current structured composition retains the leading Info dictionary but drops the whole catalog Metadata stream; plain PDFium page import also loses document metadata. Complete-source no-op Save already copies the original bytes. Explicit redaction removes metadata deliberately and must continue doing so.

Approaches: copying every packet verbatim into a recomposed document would retain recognized source conformance claims; rebuilding a whitelist of ordinary fields would discard custom properties. Choose namespace-aware selective removal of recognized conformance properties while retaining all other XML bytes when possible. This is the implementer's choice under standing user authorization to work autonomously. No routine design/commit questions, no source overwrite, no package replacement.

Use a pinned roxmltree parser for well-formedness, namespace resolution and source ranges, plus the already locked quick-xml event reader for bounded preflight before tree allocations. Do not invent an XML grammar or use regular-expression removal. No DTD/entity resolver/network access; accept standard numeric/predefined entities. Before tree parsing enforce decoded4MiB, nesting64, events131072, attributes32768 (256 per element), namespace declarations256 and name1024bytes. Each pass checks cancellation; PDF streams use strict bounded decoding; external stream-file descriptors are refused, with null optional entries allowed. Private metadata dependency copies share an8MiB allowance,32768steps anddepth64. UTF-8/16/32 packets are decoded strictly. Unchanged packets retain original stream bytes/encoding/dictionary; filtered nonUTF8 packets become valid UTF8 without a conflicting XML declaration. Reject malformed/unsupported metadata before publishing, rather than silently discard it.

Recognized removal is based on expanded namespace URI, not producer prefixes: PDF/A, PDF/UA, PDF/X and PDF/VT identification namespaces; verified PDF/E and PDF/R namespaces may be added when primary references establish their exact names. Legacy Adobe PDF/X namespace retains custom fields except GTS_PDFXVersion/GTS_PDFXConformance. Preserve namespace bindings and unknown extensions. Remove corresponding two PDF/X Info keys on recomposition without changing other Info values. This is not a universal conformance validator or a promise to detect arbitrary private claims. Do not rewrite dates/IDs or reconcile previously conflicting source Info/XMP values without an explicit properties-edit feature.

For one-source Save and multi-source composition, the first source in output order owns document-level Info/XMP, consistent with existing Info policy. Never merge unrelated authors/rights into a synthetic assertion. Keep page/object-level metadata in its original graph. Filtered metadata receives a private stream/dictionary; no mutation of an aliased source object. Bound dictionary/Info copies before allocation, stage changes before installation, and retain current atomic publication. Preserve byte-identical complete-source no-op Save and original source files. An edited/combined source must not silently fall back to a lossy route.

Wire the policy into structured catalog assembly and plain page-import Save. Keep visual Preview/Print/ImageExport routes independent of document metadata requirements. Explicit redaction stays stripping, with regression evidence. Existing native text/form mutations and no-op byte-copy semantics are not claimed to be universal conformance sanitization. A document-properties editor and general metadata-removal UI remain subsequent milestones.

Acceptance: actual failing catalog/native Save tests first; multilingual/custom/qualified RDF values and arbitrary prefixes survive; attribute and element conformance forms disappear; fake same-prefix namespaces remain; entity-normalized namespace aliases cannot bypass removal. Test malformed XML, duplicate expanded attributes, external entities, deep/large/namespace-heavy input, cancellation, compressed limits, aliased streams and repeated saves. Independently parse saved XMP and compare retained properties; verify exact unchanged page pixels/content/navigation and original bytes. Include plain and tagged/structured Save, composition order, overlays, save/reopen, and redaction. Fresh candidate desktop Save/reopen and one final fresh scoped review precede checkpoint acceptance.

References: [Adobe XMP specifications](https://developer.adobe.com/xmp/docs/xmp-specifications/), [PDF Association identification guidance](https://pdfa.org/future-proofing-xmp-identification-schema/), [roxmltree parsing options](https://docs.rs/roxmltree/0.21.2/roxmltree/struct.ParsingOptions.html), [quick-xml namespace reader](https://docs.rs/quick-xml/0.42.0/quick_xml/reader/struct.NsReader.html). The implementation must resolve normalized namespace URIs; quick-xml's raw namespace values alone are insufficient for that proof.
