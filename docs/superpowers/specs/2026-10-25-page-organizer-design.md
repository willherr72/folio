# Multi-page organizing workspace

## Intent and design decisions

The preceding split milestone is verified. Everyday page organization still requires one thumbnail/action at a time. Add an Organize pages workspace with a larger grid for selecting and manipulating multiple pages. This advances the standing autonomous quality goal; no parity or release claim. Preserve the existing sidebar's single-page reading behavior.

Alternatives: adding multi-selection directly to the narrow sidebar keeps actions close but hides large selections and couples reading/navigation state to batch targets. A dedicated grid makes the selected set and order visible. Choose the dedicated grid with an isolated draft, per-action local Undo/Redo and one Apply back to the document. This is the implementer's choice under the user's standing permission to proceed; no routine approval checkpoint. Reuse native editable export and existing page plans, not a second PDF representation.

## Selection and actions

Open from the page tools and Page actions, available when the workspace permits assembly. Snapshot the current document and adapter; select the current page initially. Show thumbnail page numbers in current draft order, selected count, active/focused option, and help for Ctrl/Shift selection. Grid is a multi-select listbox with roving focus. Plain click selects one; Ctrl/Meta toggles; Shift selects the inclusive anchor-to-target range; Ctrl/Meta+Shift adds that range. Empty selection is allowed. Arrow keys move focus and select, Ctrl/Meta+arrows move focus without changing selection, Shift+arrows extend. Up/Down use the current visual column count; Home/End reach document ends. Ctrl/Meta+A selects all only while focus is in the grid; Space applies the equivalent click modifier selection; Escape belongs to the modal unless a drag is active, when it cancels that drag. Selection alone never creates Undo or changes dirty state.

Rotate selected left/right; duplicate selected as a contiguous ordered block immediately after the last selected original, selecting the new copies; delete selected while retaining at least one page; move selected to start/end or before a chosen current page (end is pageCount+1); drag a selected group before/after an unselected target. Dragging an unselected page first selects it. Drag payload is local to the organizer; external text/files cannot authorize reordering. Drop on a selected target is a no-op. All moves preserve relative selected order and preserve unselected order. No-op moves add no history. Copies retain source identity, current crop/rotation and cloned overlays; existing bookmarks continue targeting originals. Deletion uses existing bookmark filtering, retaining valid ancestors. No batch crop/replacement in this milestone.

At most 10,000 draft pages, consistent with native export. Duplicate is refused before mutation when it exceeds that cap. All actions revalidate targets against the current draft and require assembly rights for the whole original workspace, matching existing policy. Invalid numeric drafts disable Move; targets use 1-based current page numbers. Native export remains authoritative for protection and content fidelity.

## Transaction and ownership

Dialog-local History<OrganizerFrame> owns the document plus selection/anchor/focus. Pure selection updates only present; actions commit one local step. Retain up to 100 local undo entries; do not clone immutable source/page data unnecessarily. Undo/Redo normalize selection and restore the prior action's frame. Apply is enabled only if planDigest differs from the original, commits the final arrangement as one document Undo step, and selects a valid draft page. Cancel leaves parent document/history/dirty state unchanged. Parent rejects Apply if the source document's page/bookmark references changed. Existing source registrations remain parent-owned throughout; there are no new native documents or asset registrations.

Extract selected opens one native Save dialog for the selected current draft pages in document order, with filtered current bookmarks. It does not Apply the draft or alter parent saved status. Unreadable bookmarks block extraction until explicitly resolved in the main Bookmarks panel. While export is pending, freeze the draft, local history, selection and close controls; errors stay in the organizer and preserve the draft for retry. Demo supports arranging but not extraction. Export and Apply cannot overlap. Selection and draft state do not cross tabs or persist through closing the organizer.

## Layout and interaction

Use the existing Modal focus trap and lazy Thumbnail rendering in a responsive grid. Header and footer remain reachable at 900x600; grid scrolls independently and keeps the focused option visible. Options expose aria-selected and current page position. Actions have counts and disabled states. Avoid rendering native full-page previews solely for selection. Large-document DOM/performance remains an explicit acceptance limit; existing Thumbnail intersection-based raster admission must work with this scroll root.

## Verification

Pure model: discontiguous selection, anchor/range/toggle/empty, visual keyboard columns, stable moves, no-ops, duplicate cap/deep overlays, deletion/bookmark ancestry, local undo and dirty digest. Component/App: modifiers/keyboard, local vs document Undo, Cancel, no-op Apply, drag/group bounds and external drag rejection, selection after draft changes, busy export/errors/retry, stale Apply and protection. Desktop on a five-page annotated/form/bookmarked UserUnit fixture: rotate discontiguous pages, move/duplicate/delete, local undo/redo, keyboard and pointer selection, extract current draft, Cancel/Apply/document Undo, save/reopen and narrow-window controls. Independent readers verify page order, rotation, crop, exact expected pixels, forms/notes/bookmarks/links, unchanged original. One design check and one final scoped review/correction pass; fingerprinted build and evidence ledger. No commits or source PDF overwrites.
