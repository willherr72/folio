# Graph-preserving added and imported overlay publication

## Intent and authority

Folio must save added text, text areas, images, ink, highlights and comments on combined/selected/repeated structured PDF pages without losing the original forms, tags, navigation or later editing. Imported editable annotations must be retained, changed or deleted once according to the workspace, including after recovery and native source edits. This is the next part of the user's standing autonomous quality goal. The coordinator chooses implementation details under the existing opt-out from routine approval; this document is not attributed to a new user design decision.

The accepted predecessor is `artifacts/structured-form-composition-20261030/checkpoint-evidence-final.json`, source `1ab9818dc9ba986e22d857196885ea8707f7b8fd3affbb71a2174650d3ce1493`. Its candidate and portable0.26 stay intact. Existing unsupported language/catalog/form contexts are not silently bypassed.

## Current behavior and approaches

`engine.rs::compose_imported_pdf` uses PDFium page import, renders highlight/comment annotations and some flattened ink, then `persistence::finalize` writes portable text/image/ink appearances and editor metadata. That path cannot preserve arbitrary original document graphs. `structured_source_save.rs` preserves those graphs but currently refuses added overlays and sources with imported annotations. `import_annotations` removes editable annotations and related popups from the runtime display document while retaining their original bytes and only an excluded-index set. It does not retain the source-to-workspace ownership needed for graph-preserving replacement. Some standard highlights receive a fresh random workspace ID on every load.

Approaches considered:

1. Reimport/rewrite whole source pages through PDFium, then repair tags/forms. Rejected: recreates the graph-loss problems the prior milestones addressed.
2. Write another renderer for all overlay types directly in the retained graph. Rejected: duplicates existing font/shaping/image/physical-geometry behavior and makes visual consistency harder to prove.
3. **Selected:** render only overlay appearances in an isolated staging document using existing code, then copy their bounded reachable resources into the private retained graph. Pair this with explicit source annotation ownership for replay/replacement, and typed tag/language updates. Original page content is not loaded into the staging renderer.

## Required behavior

- Cover all existing overlay variants, text areas, custom/shaped fonts, image asset embedding, physical UserUnit, nonzero page boxes, intrinsic rotation, workspace rotation/crop, and present layering rules. New text/image/ink remains portable and editable on ordinary Save. Flatten follows existing meaning: these drawing overlays become content while highlights/comments retain their established annotation behavior. Do not flatten source forms or original annotations as an incidental consequence.
- Stage the full request's overlay-only pages together so existing font/image caches share resources across pages. Empty staging pages carry the exact unrotated coordinate frame, intrinsic rotation and unit used by the existing render helpers. Apply workspace rotation/crop only in the final graph. Every generated annotation is associated with the request page occurrence and overlay ID; no ordinal guessing after layering changes. A portable image's original asset stays embedded when normal Save needs it.
- Preserve original objects and resource edges byte-for-byte except a typed, requested annotation/content change. Copy only generated resource graphs, using shared deduplication and cancellation/memory limits. Do not copy the staging catalog/page tree into source metadata, let page P pointers target staging pages, or clone unrelated source streams.
- New annotations get independently owned IDs per output occurrence. Tag ownership is explicit: preserve original authored order; append new annotation elements/OBJRs in output page/overlay order, bind ParentTree keys without collisions, and retain each occurrence's source-default language (including unspecified language). New flattened text gets its own bounded marked-content owner and language scope; do not mark semantic text/images as artifacts merely to avoid tags. No fabricated alternate descriptions or accessibility certification.
- Source graphics state may have pending clips/paths or unbalanced/opaque semantics. Flattened publication needs a proved isolation boundary; never trust q/Q alone to clear a path or clipping state. Reuse the existing bounded content/context inspection principles and refuse an unproved case before publication. Such a refusal is a documented compatibility gap, not completion of that input class.
- Imported annotation replay must know the canonical source annotation (or validated direct annotation slot), associated popup slots, original workspace identity and initial overlay semantics. Capture provenance when import succeeds, rather than trusting NM or guessing from text/geometry. A request ID alone is not proof of a source annotation. Matching unchanged imports preserves the original annotation/AP object and tag identity. Changed imports update the owned annotation in place when its unrelated metadata/typed consumers remain valid; deletion removes only its owned occurrence and typed tag/popup relationships. Unknown inbound consumers are guarded until a typed adapter exists.
- Repeated source pages have separate annotation occurrences. Editing or deleting an imported overlay on one copy cannot affect the other; unchanged copies preserve original appearance and semantic ownership. Omission of an imported overlay from a complete page draft is deletion, while missing/stale provenance is not permission to delete an arbitrary source annotation.
- Provenance is bound to immutable source bytes/page/annotation identity and travels through recovery and generated-source replacements. Runtime handles may change without losing ownership. Persist versioned binding data in the recovery source record and validate it against the recovered bytes before reuse; do not use newly randomized import IDs to reinterpret old drafts. Native fill/comment/page/text/image transactions must transfer or reconstruct bindings only after proving their annotations remain the same; uncertain correspondence must be surfaced, not guessed. No credential or file permission is granted by binding metadata.
- Keep existing form/source rights, input immutability, atomic destination publication, cancellation, font/image ownership, resource cleanup and bookmark behavior. Save/open/re-edit and recovery must work without the original font/image files. Display/print/export paths must agree with the saved representation where in scope.

## Components and sequencing

1. Isolated overlay rendering: engine-owned module builds a generated-only document using `add_highlight_annotation`, `add_comment_annotation` and `persistence::finalize`, with one shared resource cache. It returns the generated document plus exact page/overlay/annotation bindings. Test all variants and geometry against the current plain-PDF Save renderer. This is a prerequisite; public structured admission remains guarded until ownership/publication is ready.
2. Imported overlay lineage: a small bounded record/index captures original ownership and unchanged-semantic fingerprints without duplicating appearance payloads. Integrate import, generated-source transfer and recovery round trips. Existing excluded-index consumers keep their semantics. Imported standard annotation IDs become stable only through verified lineage, not inferred global uniqueness of NM.
3. Generated graph attachment and typed replacement/removal: occurrence-bound IDs, generated resource relocation, editable/flattened forms, original annotation and tag relationships, language context, bounds and cumulative validation. Share tag/language routines where their existing contracts fit; no blanket recursive string/reference rewriting.
4. Public route integration and acceptance: remove overlay guards only after every requested operation has a prepared typed transaction, then apply rotation/crop and final graph validation. Retain explicit refusal of unproved input cases and record them honestly; the entire feature is not accepted on the renderer prerequisite alone.

## Bounds and implementation choices

Keep existing per-page10,000 overlays, source/output512MiB, generated appearance64MiB, portable record32MiB, prepared-image512MiB, and retained graph100,000objects/1,000,000values/256MiB stored bytes/depth64 bounds. Add cumulative generated-metadata/lineage reservations before allocation; choose a documented16MiB metadata budget and1,000,000 traversal-step budget for the new adapters, without increasing existing limits. Small scalar/hash provenance is preferred over cloned overlays/AP graphs. Count alias traversal, repeated resources and strings; cancellation checkpoints must occur within multi-overlay pages and before publishing any candidate.

The builder may choose module split, helper names and whether an existing structure-merge helper needs a narrow interface extension. These decisions must preserve the external behavior above. No dependency, renderer, file format version or user-facing mode change is required by this design. Do not introduce a second lossy Save fallback.

## Builder-check dispositions

The one builder check is `artifacts/structured-overlay-publication-20261031/design-review.md`. The coordinator resolves its two questions as follows under standing autonomy:

1. Legacy recovery without provenance must still restore the user's draft, overlay data, fonts/images and original bytes. Do not fail recovery or silently replace recovered overlays with fresh imports. A binding may be migrated only from independently validated existing provenance; text/geometry/new randomized IDs are insufficient. If the affected graph-preserving Save cannot prove imported ownership, it must explain the missing legacy ownership and leave the draft/source/destination intact. This is a visible compatibility limit, not a claim that every historic draft is saveable; lossless general migration remains on the broad goal. New-version recovery must pass the full ownership round trip. Do not add an automatic lossy fallback.
2. Appearance agreement covers canvas/runtime display, composed preview, print-preparation PDF, page-image export and saved PDF; actual printer hardware remains a separate acceptance gate. For unchanged imported annotations, retain the original authored AP only when the editable import representation is proved equivalent. Existing portable text/ink/image records already have strict appearance validation. Standard highlight import needs equivalent bounded proof; an unproved authored AP remains a native annotation, visible and intact, rather than being removed and displayed as a reconstructed overlay. Do not claim that this makes arbitrary custom highlight artwork editable. Preserve known legacy drafts as in point1. Generated-source replacements must maintain the same admission/provenance behavior. Test a deliberately different authored highlight AP as a negative import control and a known-equivalent highlight as a positive control.

## Acceptance and review

Red/green tests first prove the current public overlay refusal and imported replay problem. Native tests cover each variant, mixed layering, shared fonts/images, same IDs on different page occurrences, actual reopened editable overlays, unchanged original form values/resources, tag ownership, source-default languages, bounds/cancellation/security, and repeated Save/edit/recovery without resource growth. Meaningful negatives include stale/forged bindings, duplicate NM, direct/aliased annotations, shared popups/unknown consumers, changed tagged descriptions, ambiguous generated-source rebinding and unsupported flatten context.

Fresh Windows acceptance: combine two tagged sources (including a form), add text/image/ink/highlight/comment, rotate/crop/duplicate, Save/reopen/edit/delete one copied overlay, Undo/Redo, Save/reopen again, and recover a draft after its original location is unavailable. Independent pypdf/MuPDF audits must compare source-derived full-page render references, original text/images and unchanged outside-edit regions, nonempty tag/navigation/form relationships, language scopes, embedded assets and absence of duplicate/stale imported annotations. Include intentionally corrupt ownership/appearance/language outputs with passing unchanged rewrites.

One builder design check and one final scoped implementation review for the milestone. Resolve small findings locally; no repeated review delegation. Keep failed evidence and exact source/candidate/helper/output hashes. No printing/accessibility/all-target/release/commercial-parity claim from partial evidence. The broader goal remains active throughout prerequisite checkpoints.
