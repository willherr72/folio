# Owned JPEG image model and publication integration

This implements parent JPEG plan phase3. The requested end state remains real, occurrence-specific PDF redaction with complete preview/apply. The first integration boundary is the owned image model; changing that boundary alone does not enable JPEG page redaction.

Use an explicit Pixels/Jpeg payload enum. Preserve the existing pixel digest domain and behavior. JPEG identity is a different digest domain containing dimensions, component count, effective transform and canonical coefficient encoding. Do not equate a JPEG with decoder-specific RGB samples. Shared aliases reuse one immutable Arc. Fresh JPEG streams contain only the canonical encoded data and the minimal image dictionary; RGB ColorTransform is explicit so a default/hint cannot be lost.

Two implementation approaches were considered: retain unvalidated original JPEGs until publication, or validate/canonicalize on registry admission. Choose admission-time validation so every owned JPEG has passed entropy/error checks and stripped metadata, and its identity is stable across serialization/reload. The codec is already bounded; charge its source work and encoded input before execution. Registry retained bytes share the existing64MiB image budget across pixel/JPEG payloads; distinct JPEG input bytes and cumulative coefficient work are also bounded. Repeated aliases are cache hits. Failed decode consumes attempted work but must not install an image or retained-byte charge.

The model exposes exact retained size, read-only pixel access, JPEG geometry/work metadata and a bounded MCU rewrite. Variant cache keys bind the source JPEG identity and exact normalized MCU mask, rather than pretending the result has a cheap pixel digest. Keep the page resolver's JPEG admission guard until MCU geometry, affected-area disclosure and opaque fill are implemented together. This guard is temporary staging, not a substitute for phase3.

Next integration: derive MCU selections from the original pixel mask without recursive expansion. Maintain separate coefficient/fill and fringe-disclosure regions, use checked outward affine bounds, and insert a unioned opaque fill immediately after the sanitized image inside the same graphics state. Preserve later content order. Cache isolated variants without mutating shared source images; charge aggregate work/output before expensive work. Reconcile repeated prepare/publish passes with transaction-wide budgets before enabling the private route.

Validation: source preservation, aliases, explicit color semantics, malformed entropy, fresh metadata-free serialization and stable reload identities; exact retained/input/work budget edges and failed-cache behavior; existing raw/Flate predictors and private area regressions. Bind actual saved JPEG payloads to independent coefficient/two-reader evidence. After geometry/publication integration, test source-owned selection, shared occurrences, other pages, text/path composition and save/reopen/re-edit, then one fresh review of the completed phase. Public UI, package and Windows acceptance remain phase4.

## Integration findings from the model stage

The existing path planner already refuses a `Do` interleaved with a pending path, so fill insertion can rely on that strict admission rule after path validation. A new issue must be solved before enabling JPEGs: a later mark can cause the whole previous black fill path to be removed. The JPEG coefficients remain sanitized, but chroma edges then become visible outside the new selection. The owned `fill-reedit-proof` counterexample changes16 pixels at1x and144 at3x in PDFium after deleting an old fill and restoring only a smaller new fill; MuPDF shows no change. This is a simulated design failure, not a currently exposed product regression.

Next implementation must give the fill and image one verified logical ownership boundary. Prefer a source-bound, canonical image/fill pair that can be collapsed into the owned image model on read and recreated immediately after each image occurrence on write. A custom record is only a hint: validate its bounded MCU mask, binding to canonical JPEG identity, exact actual fill operations for every occurrence, and that the claimed old mask is already zeroed in the JPEG coefficients. Preserve/union prior verified coverage on re-edit. Do not exempt arbitrary paths because metadata labels them as redaction. Reject stale/forged bindings and missing/mismatched fills before publication. An isolated Form is an alternative, but would add clipping/traversal behavior requiring separate fidelity proof.

Also retain these gates: outward serialization bounds for non-binary fractions, one compound union fill without adjacent seams, bounded inserted operations, reduced-resolution/chroma resampling evidence before claiming a fringe bound, and an explicit transaction-wide work/cache context across the multiple `prepare_area`/glyph-probe/publish passes. The current registry-level aggregate bound alone does not prove a whole-area-edit work ceiling. Keep the page-admission guard until these are implemented and tested.
