# Owned multi-page text-redaction previews

## Intent and authority
Advance the verified source-owned text mark toward the visible preview/Apply workflow. Prior goal turn made progress:623library passes,240native source mappings and48mark-output audits; checkpoint source/evidence/documentation hashes revalidated. User delegated implementation decisions and waived routine permission questions. This remains crate-private native/worker integration, not a newly exposed GUI/CLI/MCP tool. General public exposure still requires composition/overlay semantics, aggregate parser hardening and desktop acceptance.

## Multi-page marks and projection
Extend PageTextSelection and TextRedactionPlan to explicitly retain page_index,width,height; provide read-only internal accessors. Add mark_many(&[TextMarkRect]) with1..64valid rectangles on that page. Every input rectangle must hit at least one native glyph; positive box overlap selects whole glyphs. Iterate source glyphs once, record per-rectangle hit flags, and add a glyph only once even for overlapping rectangles. Preserve interior-space merge semantics and4096range limit. Existing mark(rect) delegates to mark_many([rect]).

Add WorkerRuntime::redact_text_marks(&[TextRedactionPlan]) with1..64plans, exactly one per page, same owned source ID/hash, and4096total ranges checked before cloning. Revalidate current source/copy/edit rights and hash once, then call the existing full-document range kernel once. Existing redact_text_mark wraps the batch method. Source IDs/ranges remain opaque; inputs from the host consist only of page indices and rectangles. Rectangles are top-left points and text-only, not all-content area redaction. Native mapping/standard-font and protection restrictions remain unchanged.

## Worker API and data
New private engine child redaction_preview.rs and tests. Engine WorkerRequest::TextRedaction(Request) dispatches to this module. PdfEngine methods are pub(crate), with reexported crate-private request/result types; no Tauri registration, CLI/MCP command or public reexport from lib.rs. The worker mints registered session owners via begin_text_redaction_session(), bounded to16active owners. A trusted host adapter retains the returned UUID; eventual adapters must supply this identity themselves, never accept an untrusted owner UUID from a request body. Unknown/released owners refuse before inspection. Release removes the owner registration, so late requests cannot recreate a closed session; no unbounded revocation tombstones are needed.

Methods: begin_text_redaction_session()->String; preview_text_redaction(owner_id,source_id,marks)->PreviewInfo; text_redaction_preview_bounds(owner_id,preview_id,page_index,offset,limit)->BoundsPage; apply_text_redaction_preview(owner_id,preview_id)->DocumentInfo; discard_text_redaction_preview(owner_id,preview_id)->(); release_text_redaction_owner(owner_id)->(). Preview input1..64mark records {page_index,rect{x,y,width,height:f64}}; validate before copying into worker requests. Each preview belongs to exactly one immutable source and one owner. Group by page; inspect each selected page once and create one mark_many plan per page, then remove all plans in one kernel call.

PreviewInfo contains preview_id,source_id,candidate DocumentInfo,removed_characters,affected_blocks,omitted_metadata categories,expires_in_seconds and at most64page summaries. Each page summary explicitly includes page_index,width,height,selected_glyph_count and union extent of full affected boxes. It does not echo removed text. Full measured boxes are paginated via BoundsPage: offset and limit1..1000, returned boxes and total count. Page not in preview, offset past length, or invalid limit refuse. Bounds are review/display data, never supplied back as removal authority.

## Candidate ownership and capacity
WorkerRuntime owns PreviewStore. Store at most4pending previews,128MiB aggregate candidate source bytes and32MiB aggregate retained glyph-box payload. Each source/output retains the existing64MiB bound. At most250000glyphs/page and1MiBsource characters bound an individual plan; after each page plan, check cumulative geometry/ranges before retaining it. A single in-flight next-page plan can transiently add at most8MiB of box data before capacity refusal; do not misstate retained capacity as total-process peak memory. Metadata/page counts are separately bounded. Check slot availability before work and candidate-byte capacity before registration. Capacity errors preserve existing previews and source documents.

Register a new native candidate only after complete source-bound removal succeeds and budgets permit. Cache records source ID/hash, owner, candidate ID/hash, an Arc clone of candidate bytes as its allocation ownership proof, creation Instant, and owned page geometry. Arc cloning does not copy candidate bytes. Validate original_path linkage for overwrite protection; candidate gets the source original_path, unprotected policy only and no original annotations/fonts/images (kernel rejects those dependencies). Do not import original object graphs or clear original source data.

A pending candidate cannot be the source for another preview; Apply first. This avoids cascading dependent pending graphs. Multiple previews of the same ordinary source are allowed within capacity. Apply checks current source open/rights/hash and candidate still has the owned Arc allocation and expected byte hash; only then consumes the lease and returns candidate DocumentInfo to the caller. The original remains open. Apply is one-shot; adopted candidates become caller-owned and are not removed by later owner release or original-source closure.

Discard verifies the owner before removing a lease and closes only its owned candidate. Wrong-owner calls cannot consume or close another owner's preview. Cleanup verifies candidate ID and Arc allocation identity before touching the document table; if an entry has been replaced, release the lease without deleting an unrelated document. Creation failure must leave no new registered source. If sending a successful owner-registration response fails, release that owner. If sending a successful Preview response fails, discard its lease/candidate; if sending Apply success fails, discard the newly adopted candidate, because the caller never received ownership.

## Expiry and closure
TTL15minutes by Instant; prune expired pending entries at each preview operation. Access/Apply enforce expiry independently of a previous prune. No sleeping/background timer or touch-based lifetime extension. Tests may alter internal creation Instant, not wall clock. Owner release unregisters that owner and removes only that owner's pending previews. A later Preview or bounds/Apply with the released token refuses; release itself may be idempotent. Closing an original source invalidates all its pending previews; closing a pending candidate invalidates that lease. Hook both close_document and discard_unpublished_source through nonrecursive cache detachment, then close owned candidate resources using the existing rollback path. Unrelated documents and adopted candidates remain untouched. Shutdown drops the worker's document store as before.

## Rights and limits
Inspection, preview and Apply enforce current edit+copy rights and reject print-only/protected-policy sources. Bounds queries also revalidate owner, source/candidate identity and rights; rejected stale previews may be invalidated and their owned candidates closed. Discard/release are cleanup and do not require rights. No file writes. No claim that initial lopdf parsing has an aggregate hostile-stream memory bound;64MiBinput/per-stream and existing kernel budgets remain. Resolve broader parser limits before external exposure. No native UI rebuild, package overwrite, commits or changes to original PDFs this milestone.

## Acceptance
Native multi-page/multi-block fixture: repeated block ordinals on separate pages, two discontiguous marks in a block, overlapping duplicate marks, text near page edge, following unselected text and one untouched page. Use explicit small multi-page cases plus all prior focused tests. Confirm selections remove exactly the intended ranges, untouched pages remain identical in independent text/raster checks, and original bytes/doc counts unchanged. Retain failed evidence.

Lifecycle tests: wrong owner, one-shot Apply, duplicate Discard, original/candidate closure, late edit/copy/policy changes, changed source/candidate bytes, expiry, capacity refusal, release isolation and dropped Preview/Apply receivers. Prove cleanup never deletes a swapped unrelated candidate allocation and never deletes adopted results. Boundary tests for exact count/aggregate byte/geometry capacity without huge real allocations may use small private configurable limits, while production limits stay constants. Source-derived native mapping regression covers multiple blocks/pages and page-edge selection. Existing48mark outputs and240source mapping tests remain passing.

Independently inspect exported adopted multi-page PDFs with MuPDF/pypdf and checked-in PDFium where practical; check removed text/decoded graph absence, all unselected glyph positions, and exact pixels outside source-selected glyph ink with fixed AA allowance. Measure whole-glyph boxes and use source-only masks. One builder check, one final scoped review, local corrections without re-review. Finish with relevant native/library gates, fingerprints and persistent checkpoint.
