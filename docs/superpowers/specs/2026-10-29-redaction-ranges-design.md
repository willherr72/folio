# Source-bound partial text redaction

The prior goal turn made progress: private whole-block removal is verified in artifacts/redaction-core-20261029/checkpoint.json. This milestone advances stage B of the structural-redaction design with character origins and partial text removal. The user delegated implementation choices and opted out of routine design questions. Decisions here are coordinator choices, not a claim of user-selected details.

## Intent and approaches
Remove a selected substring while retaining all other characters at their original locations, including later shows and lines. Reuse the freshly rebuilt, source-bound document pipeline rather than editing a saved file incrementally.

Alternatives considered: deleting bytes alone moves following text; replacing selected text with blanks retains spacing only for fixed-width cases; repositioning every remaining glyph with Tm disrupts the text line matrix and multiplies rendering changes. Chosen approach: replace removed glyphs with numerical TJ advances, retaining all original TJ numbers and non-show operations. Source geometry comes from an interpreter of the same canonical operations, not client-provided coordinates.

## Contract
Keep the API private. Reuse milestone A's full-document admission, opaque block IDs, fresh minimal graph publication and all input/output budgets. Add `inspect_standard_glyphs(&Document) -> EngineResult<Vec<GlyphBlock>>`; each GlyphBlock contains its TextBlock and a glyph list with byte offset, raw printable-ASCII code, baseline origin [f64;2] and endpoint [f64;2] in unrotated PDF page points. These are advance geometry, not ink rectangles or area-redaction bounds. Source code offsets match the decoded ASCII operand text; default StandardEncoding Unicode semantics are not mislabeled as ASCII reader Unicode.

Add `TextRange { selection_id:String, start:usize, end:usize }` and `remove_standard_text_ranges(&Document,&[TextRange]) -> EngineResult<RedactedTextRangesPdf>`. Ranges are half-open decoded-operand byte intervals within an inspected block. Recompute the whole-document binding; reject empty/unknown/stale/out-of-bounds ranges and overlaps/duplicates. Adjacent disjoint ranges are allowed. Maximum 4096 ranges, 1 MiB selected characters; count distinct affected blocks separately from removed characters. Return fresh bytes, removed_characters, affected_blocks and omitted_metadata. Never echo removed text into metadata. No source mutation, output file writes or public command.

## Metrics and geometry
Reuse the existing proved StandardFont encoding/advance tables via one crate-private helper returning 95 integer nominal widths for ASCII codes 32..126. Build these tables only for the already admitted standard-font identity. Default StandardEncoding and WinAnsi differ at punctuation; decode the source code using the actual nominal encoding before consulting width tables. No new dependency or imported font program.

Track CTM plus font, font size, horizontal scaling, character spacing, word spacing, leading and rise in q/Q graphics-state frames. Track Tm/Tlm explicitly: BT resets both. Match Folio/PDFium by saving and restoring both with q/Q; outside text objects this has no effect on a subsequent BT reset. The PDF 2.0 erratum explicitly requires their inclusion within text objects. Tm sets both; Td/TD/T* update Tlm then Tm; TD also sets leading. Canonical quote shows already expose Tw/Tc/T* state. Concatenate cm and text translations in PDF order. A glyph advances `(width/1000*size + Tc + (code==32 ? Tw : 0))*Tz/100`. Origin is the CTM/Tm transform of [0,rise]; endpoint transforms [advance,rise]. Existing TJ numbers advance by `-number/1000*size*Tz/100`. Track every show, string fragment and numeric adjustment in original order.

For a removed glyph, emit a TJ number `-(width + 1000*(Tc + applicable Tw)/size)`. Retain original TJ numeric values and contiguous retained string slices; never coalesce source adjustments with new compensation or replace the line matrix. Preserve one compensation per removed glyph initially to avoid changing accumulation order. Bound computed numbers/coordinates to finite magnitudes <=1,000,000 and reject degenerate/unrepresentable compensation. Recheck the serialized result with the same admission/geometry parser; output must remain within the original array, operation, text and byte limits. If splitting is necessary to keep a generated TJ array <=4096 elements, emit adjacent TJ operations without changing state. Preserve untouched show objects exactly.

Floating-point compensation must be tested against independent readers; a mathematically correct displacement alone is insufficient evidence. Successful representative output must preserve unaffected origins within 0.002 pt and exact raster outside selected glyph ink in acceptance fixtures. Do not weaken a failed raster check by enlarging masks or rasterizing pages. Investigate discrepancies before declaring the milestone verified.

## Design review rulings
The single builder check is artifacts/redaction-ranges-20261029/design-review.md. All three questions are resolved here. The matrix probe uses the checked-in PDFium DLL (hash recorded) and MuPDF on four synthetic PDFs. PDFium restores Tm/Tlm within BT; MuPDF retains their current values, for both PDF 1.7 and 2.0 headers. The source already renders differently. Use the native/PDF 2.0 semantics for reported selection positions and preserve each reader's own original remaining text in independent acceptance. Do not normalize the source layout to hide this difference. Reference: https://pdf-issues.pdfa.org/32000-2-2020/clause09.html .

After writing, reparse the generated bytes and recompute geometry; compare the full sequence of retained raw codes and both baseline endpoints within 0.002 pt. This detects serialized f32 compensation drift even when intermediate f64 arithmetic was exact. Failure returns no output. Retain original Tm/Tlm and TJ numbers; never move unrelated text to make a test pass.

Count generated operations and tokens before growing the output vector: at most 100000 operations and 500000 lexical-equivalent tokens document-wide, 16 operands/operation and 4096 array elements. Split generated TJ arrays into adjacent TJ operations at the array limit; refuse if the global limit is exhausted. Keep original byte, object, text and serialization bounds. Representable compensation and finite geometry are admission requirements; the new API does not narrow whole-block removal.

## Runtime fidelity correction
Native raster evidence showed that a mixed TJ array combines adjacent removal numbers into a single kerning in PDFium, changing float accumulation from an ordinary Tj. For nominal Tj with Tc=Tw=0 and Tz=100, emit separate retained-text shows and numerical-only TJ moves; keep individual removed-glyph advances in order. Active spacing/scaling and preexisting TJ programs retain general mixed compensation. The native fixed-region regression failed915 channels before correction and passed afterward. All96 saved cases then passed both readers' exact outside-pixel checks.

PDFium collapses consecutive logical spaces during extraction after a deletion. The auditor therefore checks every native visible glyph plus exact raw remaining operands and every MuPDF character/space. MuPDF's advance boxes omit italic ink overhang; its exclusion mask is an isolated render of selected SOURCE glyphs, using source operators and independently read source origins, with fixed2pixel antialias dilation. No output pixel contributes to the mask. Five negative controls include missing compensation, hidden hex payload, ordinary paint and paint in empty advance-box space. These are verifier corrections, not relaxed raster acceptance.
