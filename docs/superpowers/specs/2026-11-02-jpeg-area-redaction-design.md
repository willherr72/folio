# JPEG area redaction: preserve unselected coefficients

## Objective and evidence

Support meaningful image-area redaction in ordinary JPEG-containing PDFs while preserving unredacted document content. This remains part of the full public preview/apply goal, not a replacement for it. The current private publisher still refuses DCTDecode. No JPEG capability is claimed from this design alone.

`artifacts/area-jpeg-probe-20261102` establishes why a raw-pixel conversion is insufficient. Eight owned 64x48 fixtures cover Gray and RGB, baseline/progressive, and RGB 4:4:4/4:2:2/4:2:0 sampling. PDFium GetBitmap agrees with Pillow in these cases, but the existing Rust decoder differs by up to 3 channel values. PDFium-based normalization preserves Folio's rendering, yet the independent reader differs by up to 102 channel values at subsampled color edges. Merely loosening a raster tolerance would conceal the failure.

A separate coefficient-domain prototype replaces only selected blocks, preserving quantization tables, component identifiers and sampling factors. All 42,240 unselected coefficients match exactly; all 3,840 selected coefficients match independently specified replacement blocks. Both native PDFium and PyMuPDF preserve raster samples outside the declared block footprint plus measured chroma-resampling fringe at 1x and 3x. Original/recompressed negative controls fail for selected/outside coefficients respectively. This proves the approach for the owned corpus, not arbitrary-input safety, generalized geometry or a production codec.

## Chosen architecture

Use a bounded in-process JPEG coefficient transform. Do not invoke a shell utility in the application, apply lossy recompression, normalize all JPEGs to one decoder's RGB samples, or silently remove entire images. JPEG block granularity must be disclosed in preview: the native affected area may exceed the user's drawn rectangle. Raw/Flate images retain the existing exact pixel behavior.

Represent image payloads explicitly as pixels or admitted JPEG coefficients/encoded data. Keep source identity, dimensions, color interpretation, canonical encoded bytes and immutable ownership. Hash JPEG payloads in a distinct domain so equivalent pixel arrays do not cause an unmodified JPEG to be replaced by a different encoding. The pure publisher must not acquire hidden global renderer state.

Use the existing interval-based source-pixel selection to choose JPEG minimum coded units (MCUs). Build the MCU set from the original selection before expanding any masks; otherwise in-place expansion can cascade into neighboring blocks. Rewrite all component blocks belonging to chosen MCUs. Keep a separate affected-region mask for block expansion and reader resampling fringe. Never feed a disclosure-only fringe back as another selection. Non-divisible image edges must clip to actual dimensions.

Black replacement is defined in coefficient space. All AC coefficients become zero. For Gray or uninterpreted RGB components, DC is `-ceil(1024 / Q00)`; for YCbCr, use that value for Y and zero for both chroma components. These constants target black component interiors; the production gate must verify every admitted quantization endpoint. Initial quantization admission is 8-bit tables with values 1–255; reject zero entries and 16-bit quantization tables until separately verified. PDF ColorTransform and Adobe marker precedence determine interpretation; do not substitute the codec's filename/JFIF heuristic. Preserve the PDF image's effective color interpretation in fresh output.

Coefficient-black is not a full-area opacity guarantee: chroma resampling can mix retained neighbors at the block edge. The final publisher must paint an opaque black fill covering the complete selected region, including boundary samples. Place it immediately after the sanitized image in the same effective transform/clipping/paint order, before following content, or use an equivalent independently verified treatment. The coefficients must already be removed; a visual cover alone is forbidden. Build a union of affected block footprints so adjacent fills cannot leave antialiased seams. Preserve surrounding and later content according to the combined source-selection rules, and keep any disclosure-only resampling fringe separate from selected content removal.

Coordinator correction evidence: `opaque-fill-2` reproduces 59 nonblack pixels inside the selected region with wrong fill order in the native reader; correct order makes every selected pixel black in both readers at 1x/3x while preserving pixels outside the declared footprint/fringe. A cover-only control is opaque but retains the original JPEG and is explicitly rejected as data removal. This is still a fixed aligned fixture proof, not generalized publication acceptance.

The prototype observes a one-pixel horizontal and/or vertical fringe for subsampled images in its two readers. Production must derive and test a conservative supported-reader bound, including rotation, shear, reflection, scaling and partial MCU edges. This is not a universal bound for every possible JPEG resampler. The declared affected area must cover all observed changes; unresolved cases must not silently pass. Coefficient equality remains the independent preservation invariant outside rewritten blocks.

## Native codec and resource contract

The proof uses libjpeg-turbo 3.1.0 commit `20ade4dea9589515a69793e447a6c6220b464535`, matching the renderer's source version, fetched from the upstream repository and pinned by archive/source hashes. It is development-only. Upstream currently publishes 3.2.1 with later fixes; production integration must use the supported reviewed source release and repeat this proof on it. Do not deploy the prototype executable or copy its default fatal-error handler into the app.

The same proof has now also passed on the official 3.2.1 source tarball, verified against upstream asset SHA-256 `c27ad72a68da151177929aa969ae773a2da5ac2af9ce946079314fdac8cece7f`. Its arithmetic codec options were disabled. `coefficient-evidence-321` retains the eight results and controls. This selects the supported foundation source; vendoring, build/source fingerprinting, license collection and production error/resource containment remain unfinished.

The production C boundary must contain all setjmp/longjmp error handling, convert warnings/truncated-input recovery into a refusal, clean up on every exit, and never unwind through Rust. Expose immutable input bytes, validated dimensions/components/effective transform, an MCU mask and explicit input/output/workspace limits. Return an owned bounded output and a structured status; no native filenames, environment paths or publication side effects.

Bound compressed input and output, total retained input/output resources, coefficient storage including padded blocks, decoder allocation requests and scan work before corresponding work. A codec `max_memory_to_use` hint alone is not a total allocation bound. Use a measured allocation-accounting backend shared by compressor/decompressor state, or prove an equivalent full bound; include destination growth and transient buffers. Do not claim exact total RSS from logical payload accounting. Preserve the existing image dimensions, pixel, occurrence and geometry limits.

Validate complete marker framing and EOI consumption without accepting concatenated/trailing payloads. Reject unsupported precision, arithmetic/lossless/hierarchical modes, dimensions/components inconsistent with the PDF, unsupported sampling, contradictory color hints and unsupported PDF Decode/mask/profile semantics. Cap scans and aggregate coefficient processing. Strip EXIF/comments/thumbnails and unrelated markers rather than copying them into the new PDF; retain or generate only the minimal verified color markers needed for fidelity. Test APP metadata between progressive scans as well as before them.

Integrate fresh JPEG output into occurrence-specific resource publication. Unmarked occurrences retain their coefficient values, even when another occurrence is sanitized. Cache keys must bind original immutable image identity and normalized MCU selection; a resulting-pixel digest cannot be computed cheaply without codec work. Check remaining output limits before allocations, and preserve failure atomicity. Source inputs stay unchanged, candidates remain unregistered until the existing adoption flow accepts them, and source identity must survive save/reopen/re-edit.

## Acceptance before admission

1. Bounded codec tests cover valid baseline/progressive Gray/RGB, sampling modes, color-transform precedence and exact source coefficients; malformed/truncated/concatenated streams, warnings, metadata, budget endpoints and repeated failure cleanup refuse without leaks or process termination.
2. Generalized region tests cover disjoint selections, MCU edges, partial final blocks, transformed images, unchanged shared occurrences, full selected-area opacity including resampled boundaries, and adjacent-fill seams. Compare coefficients and native/independent renders using source-derived bounds; use effective negative controls for cover-only retention and wrong paint order.
3. Actual private area publication saves and reopens combined text/path/JPEG results, strips old selected image data and metadata, preserves unselected content, and supports another edit. No cover-only or orphan-payload acceptance.
4. Review the complete delta and run appropriate serial native gates. Package/host/Windows acceptance remains required before public UI claims. The prototype's eight owned cases are not those gates.
