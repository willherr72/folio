# Folio v0.6 persistence and compatibility design

The user approved continuing the agreed release sequence: issues #6 and #7. This is an architectural persistence change with a separate compatibility corpus workstream.

## Portable editable PDF

Default Save a copy emits a standalone PDF. Folio-created text and ink/signatures use standard FreeText/Ink annotations with versioned Folio metadata and valid appearances. Highlights/comments keep their v0.5 format. No sidecar or original-source dependency is introduced. Avoid embedding duplicate source PDFs.

On open, validate the metadata and appearance relationship before replacing owned annotations with editable overlays. Unsupported versions, malformed/stale metadata or unrepresentable external modifications leave the visible native annotation intact. Original source bytes remain immutable. Repeated save/open cycles must not multiply objects or content.

TextOverlay gains optional rotation (0/90/180/270), default zero, around the text's local top-left x/y anchor in normalized displayed source coordinates. This preserves text orientation when a rotated exported page becomes a new source. Ink paths and annotation metadata map through the same PDF/page coordinate transforms. Page order, duplication, deletion, crop and rotation remain document operations without source-file dependencies.

A native ExportRequest flatten boolean defaults false. A clearly named Flatten text and ink option uses page content for those additions, preserving review annotations. The UI states the loss of text/ink editing handles. Flattened export does not mark the editable workspace saved. The main Save a copy and Ctrl+S actions stay direct and editable by default.

Recovery gains an appropriate import-version migration for newly editable source annotations without resurrecting deleted overlays. Test v0.4/v0.5 compatibility, malformed versioned data and unavailable original files.

## Compatibility corpus and measurements

Use only synthetic or redistributable fixtures with recorded provenance and font licenses. Version small representative PDFs; generate large files into ignored artifacts. Cover image-only scans, dense text/tables, embedded unusual fonts, mixed page sizes, crop/rotation, a 300-page document, and a substantial scanned PDF.

Measure native open/render/scroll traversal and process memory alongside browser/desktop warm tab behavior. Record CPU/RAM/OS, fixture sizes/settings/checksums, commands and results. Assert stable functional invariants, repeated work and cache bounds; establish timing budgets from measurements rather than arbitrary global thresholds.

## Release verification

Run meaningful unit and native multi-session roundtrips; independent MuPDF/pypdf appearance checks; browser rotated-text/search tests; corpus checks and benchmarks; built Windows save/reopen/re-edit, flatten, source-move and crash recovery workflows. Review fixes before committing/publishing v0.6. Close issues only after their criteria are verified. Retain existing development worktrees.
