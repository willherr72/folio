# Packaged Windows printing acceptance

Close the end-to-end printing gap on the verified Folio0.28 portable package. Existing native tests cover preparation, physical placement, annotation visibility and direct virtual-device spooling, but do not establish the current packaged UI → Windows Print dialog → driver → saved-file workflow.

Use only explicitly selected Microsoft Print to PDF, fresh owned output paths, and an isolated app/profile. Never submit to the default printer by assumption or change global printer configuration. Every native-dialog action must bind process birth, executable path/hash, exact dialog ownership and unique controls. Record the selected virtual printer immediately before confirmation. Preserve all originals, prior packages, failures and user app processes.

Task1 is an observation gate: inspect the actual owned native controls, cancel them, then produce one explicit virtual-printer probe. Inspect driver output representation and printer metrics before committing to a full-content oracle. Do not replace whole-content fidelity with a few colored-pixel assertions. If the driver preserves embedded raster pixels, prove full decoded image identity and placement independently; otherwise derive and test the actual driver transformation or retain that gate as incomplete. No tolerance is chosen merely to pass an observed output.

Use an authored three-page fixture with distinct geometry/content, original text to edit, a form answer, print-only/screen-only annotations, and a cropped/rotated/UserUnit page. Exercise current unsaved edits and retain a reference of the intended page state. Cases: Folio-dialog Cancel; Windows-dialog Cancel; save-output Cancel; invalid page range; all-pages fit portrait; range1,3 fit landscape; current page2 actual portrait; all-pages actual landscape; current oversized page3 actual portrait with expected clipping. Inspect page count/order, physical sheet size/orientation, placement, complete content, edits/forms/annotation visibility and preserved input/session state. Negative controls must reject omitted content, wrong page/order, wrong scale/orientation and unbound output/helper identity.

The installed virtual printer currently reports Letter, color, one-sided. Capture this independently again during execution; do not infer expected paper from output alone. Device-pixel rounding may be accounted for only from recorded printer metrics and the stated placement formula, not a discretionary image tolerance. Printing is rasterized by the existing product; searchable printed text is not currently promised.

No product change is planned unless a demonstrated defect requires correction. Such a defect needs a failing regression, scoped fix and relevant fresh build/test acceptance. Otherwise retain the exact accepted package and avoid gratuitous rebuilding. Native/physical-printer tests, arbitrary drivers, color management, accessibility and commercial parity retain explicit limits.

One final fresh scoped review after implementation/evidence, with corrections in one pass. Standing user authorization permits autonomous local work and opts out of routine design/branch approval prompts. No commits, cleanup of prior evidence, public publication or user-app restart.
