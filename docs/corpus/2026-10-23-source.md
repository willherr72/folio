# Export memory and Windows publication checkpoint

The final combined source passed on 2026-10-23 UTC. Evidence is in
`artifacts/corpus-current-20261023/verification.json`; historical failures remain
alongside the final results. This is a source/debug checkpoint, not a new portable

## Measured workload

Three fresh release processes per fixture passed before and after the fix: the
300-page dense document and the 40-page, 96.19 MiB synthetic scan. Phase snapshots
located the scan peak during export. Composition now releases superseded serialized
bytes before serialization and the parsed document before protection reparses the
output. Preservation, protection and output limits remain in place.

| Scan metric | Before | Final combined source |
| --- | --- | --- |
| Sampled peak private memory | 652.46–652.73 MiB | 524.38–524.95 MiB |
| Sampled peak working set | 554.46–554.63 MiB | 497.29–497.37 MiB |
| Median edited/reversed export | 269.98 ms | 535.17 ms |

Private memory and working set are distinct measurements. The final run was slower;
there is no speed improvement claim or instrumented attribution of that difference.
The shared machine has about 95 GiB RAM. These are synthetic workloads, not dedicated
hardware measurements or physical 8 GB laptop acceptance. Full timing data, including
the dense document, is in `comparison-final.json` under the evidence directory.

## Windows save reliability

Full native runs repeatedly encountered error 5 at final PDF publication. A controlled
Windows handle denying delete sharing reproduced that failure before the fix.
Publication now retries the same synced temporary file for Windows errors 5, 32 or
33, with at most 11 attempts and ten requested 25 ms sleeps. It never rewrites an
existing destination in place or changes its permissions. Persistent denial remains
an error; other errors and non-Windows paths return immediately.

The transient-lock, persistent-lock and read-only destination checks pass, preserving
old output on failure. Original image rotation assertions remain intact. The identity
of the original external locker is unknown. Attempts and requested sleeps are bounded,
not total wall time; cleanup is best effort if the OS also denies deletion. Runtime
coverage specifically exercising errors 32/33 and non-Windows platforms is absent.
