# Folio v0.9.0

**More fonts…** now matches the print dialog: search installed faces, preview your text, and choose **Apply font**. The layout works in light/dark themes and keeps its actions accessible in smaller windows.

Existing-text editing now reuses verified embedded TrueType fonts, including supported subsets. If the subset lacks a needed letter, your draft stays in the dialog: choose a substitute font, preview it, then apply the text edit. The resulting PDF embeds that font and retains the text's size, color and baseline, with checks protecting nearby source content.

Supported runs remain horizontal Latin text with reliable character/glyph mappings. Ambiguous fonts, complex scripts, positioned run groups and nested-form editing remain outside this release. [Support details](../existing-text-editing.md).

Issue #13's investigation has a reproducible shaping/reader probe and three implementation stages: [#14](https://github.com/willherr72/folio/issues/14) for shaping and Unicode, [#15](https://github.com/willherr72/folio/issues/15) for positioned text and forms, and [#16](https://github.com/willherr72/folio/issues/16) for bounded wrapping. The probe found a real combining-mark copy incompatibility across readers; complex-script editing is not enabled by this research. [Investigation](../complex-text-design.md).

Download the Windows x64 portable ZIP, extract it, and run **Folio.exe** with the resources folder beside it. WebView2 Runtime is required.

Verified with 209 frontend tests, 92 native tests, 12 browser scenarios and the packaged Windows workflow. Independent readers confirmed replacement extraction, exact font bytes and unchanged surrounding pixels. [Verification report](../verification-v0.9.0.md).
